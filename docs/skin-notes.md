# GRV6 skin - developer notes

Mixxx 2.5.0 legacy XML skin, 1920x1080. Copy the folder `GRV6` to `~/.mixxx/skins/`, restart Mixxx (Ctrl+Q), pick **GRV6** in Preferences > Interface.
The XML, themes and images are generated by `tools/build_skin.py` and `tools/make_images.py`; `GRV6/style.qss` is edited by hand.
These are working notes: the controls the skin, the controller script and the patched build share, and the Mixxx quirks met on the way.

## The two deck controls (for the controller script)

| Control | Values | Default at skin load | Written by | Read by |
|---|---|---|---|---|
| `[Skin],grv6_left_deck` | 1 or 3 | 1 | controller script, and the on-screen test buttons (test skin only) | every "left" widget stack |
| `[Skin],grv6_right_deck` | 2 or 4 | 2 | controller script | every "right" widget stack |

- The value **is** the deck number. Each side is a `WidgetStack` whose page index equals the value (page 0 and the other side's decks are empty pages).
  Values outside 1/3 (left) or 2/4 (right) show an empty side.
- Not persistent: every skin load resets to 1 and 2 (the skin loads, so the script must set them **after** the skin exists - set them when a DECK button is pressed, or from a one-shot `engine.beginTimer(1000, fn, true)` after `init()`).
- They are toggle push buttons created by the skin. Set them with `engine.setValue("[Skin]", "grv6_left_deck", 3)`. Do **not** MIDI-map them with `<normal/>` (that would toggle 0/1).
- Everything channel-related on screen follows: waveform, overview, deck panel, cover, title, time, BPM, key, meter, buttons, the strip under the panel (which shows the *other* deck of that side), the narrow deck column, the Browse deck cards, and the Sampler tab headings.

`show_maximized_library`: 1 shows Browse, 0 returns to Main. Your mapping toggles it, so the Browse button on the controller works.
`[Library],load_error` and `[Library],app_error`: both cleared on the spot by the controller's BACK button.

## Attributes set on skin load

`[App],num_decks` = 4, `[App],num_samplers` = 16, `[App],num_preview_decks` = 1, plus the skin controls above.

## Mixxx controls read (display only)

Per deck, `[Channel1]` ... `[Channel4]`:
`track_loaded`, `play_indicator`, `playposition`, `bpm`, `pitch`, `file_key`, `sync_leader` (LEADER tag, any value above 0), `sync_mode` (SYNC tag when equal to 1),
`loop_enabled`, `beatloop_size`, `visual_bpm`, `visual_key`, `vu_meter_left`, `vu_meter_right`, `rate` (tempo %), `rateRange` (the +- value),
`time_elapsed`, `time_remaining`, and the waveform marks `cue_point`, `hotcue_1_position` ... `hotcue_8_position`, `loop_start_position`, `loop_end_position`.
Track properties (title, artist, track number, duration, cover art) come from the loaded track.

Others: `[App],audio_latency_usage` (top bar "CPU"), `[Master],vu_meter_left/right` (top bar MASTER),
`[QuickEffectRack1_[Channel1]],enabled` and its chain preset name (CFX), `[EffectRack1_EffectUnit1],enabled` and its chain preset name (FX STRIP),
`[Controls],ShowDurationRemaining` and `[Controls],TimeFormat` (how NumberPos prints time), `[PreviewDeck1],play`, `[SamplerN],play_latched`.

## Mixxx controls written (buttons on screen)

Per deck: `pfl` (CUE = headphone cue), `play` (PLAY), `sync_enabled` (SYNC), `quantize` (QUANT), `keylock` (KEYLOCK), `slip_enabled` (SLIP), `LoadSelectedTrack` (Browse LOAD 1-4).
Samplers 1-16: `cue_gotoandplay` (left click), `cue_default` (right click), `LoadSelectedTrack` (LOAD).
`[PreviewDeck1],LoadSelectedTrackAndPlay` (PREVIEW, on-screen and hardware); the preview deck's title, artist, comment, stars, `visual_key` and `bpm` are read. Clicking the big time number changes `[Controls],ShowDurationRemaining` (Mixxx built-in behaviour).

## Changes in version 0.5 (needs the "stable 2" patch build)

- **Track highlight:** solid orange, dark text (was a dark brownish colour barely different from an unselected row).
- **Track-load error banner:** needs `mixxx-build/patches/load-failed-banner.patch`. On stock Mixxx a failed load (USB pulled) shows a modal popup with no way to dismiss it on a kiosk with no keyboard/mouse - it hangs Mixxx until restarted. The patched build sets `[Library],load_error` instead; the skin shows a red banner across the top ("TRACK NOT FOUND - check the USB - press BACK to dismiss") bound to it. The controller's BACK button (channel 6, note 0x65 - previously a plain `[Library],MoveLeft` binding) now also clears it on press, via `PioneerDDJGRV6.backButton` in `controller/DDJ-GRV6-Custom-scripts.js`; MoveLeft still works exactly as before. It also clears itself the next time any deck successfully loads a track, as a safety net.
- **Beatgrid:** needs `beatgrid-ticks.patch` (stable 2). Downbeat markers become thin red bars, every beat becomes a short tick at the top/bottom edge, instead of xdj-hardware's large red triangles and full-height white lines. Skin-side: unchanged (this is drawn by Mixxx itself, not the skin).
- **Effect ring-out:** needs `effect-ring-out.patch` (stable 2). Echo and Reverb now ring out for up to 6 seconds after their unit is disabled, instead of cutting off after one audio buffer. Every other effect, and every other effect rack (CFX included), is unaffected. Skin-side: unchanged.
- **Every other Mixxx error, dismissible too:** needs `error-dialog-banner.patch` (stable 2). Almost all of Mixxx's OTHER errors (database, library import/export, broadcasting, recording, controller-script exceptions) go through one shared function, `ErrorDialogHandler`, which is patched the same way as the track-load banner: sets `[Library],app_error` instead of a popup, skin shows "MIXXX ERROR - see mixxx.log - press BACK to dismiss", BACK clears it. The real message only goes to `mixxx.log` (a skin control can't carry text).
- **Sound device startup:** needs `sound-device-startup-retry.patch` (stable 2). If the configured audio devices fail to open at Mixxx startup, it now retries a few times (up to 6, 1s apart) instead of showing an undismissable dialog; if it still fails, Mixxx exits so your `~/.xinitrc` restart loop tries again. Startup only, no skin change.

## Changes in version 0.6

- **INFO button removed, merged into PREVIEW:** the separate on-screen INFO button (`[PreviewDeck1],LoadSelectedTrack`) is gone. The single PREVIEW button now loads, plays, and shows the info block in one press, on-screen and on the hardware GROOVE CIRCUIT B5 PREVIEW button alike.
- **Hardware PREVIEW now matches the on-screen button:** previously the hardware button only did `LoadSelectedTrackAndPlay` and never set `[Skin],grv6_info_valid`, so the info block stayed blank. It now calls a new script function, `PioneerDDJGRV6.hardwarePreview` (`controller/DDJ-GRV6-Custom-scripts.js`), bound in place of the old plain `LoadSelectedTrackAndPlay` binding (status 0x96, midino 0x36).
- **Symmetric Browse deck cards:** the two Browse cards for the focused decks are now a fixed 952px each (was flexible width, so a long title on one deck shrank the other's card and the pair no longer lined up in the middle). Skin generator only (`tools/build_skin.py`), no controller change.
- **Track highlight, more visible:** the selected library row now also gets bold text and a thin light top/bottom edge, on top of the existing solid-orange background.
- **Non-gated hot cues:** needs `mixxx-build/patches` unchanged, mapping-only fix. Stock Mixxx "gates" a hot cue pressed while paused - it previews (plays while held, jumps back and stops on release) instead of just jumping there and continuing to play. All 32 pad hot-cue bindings (decks 1-4, pads 1-8) now go through `PioneerDDJGRV6.hotcuePlay`, which sets `play = 1` immediately before activating the hot cue so Mixxx always takes its non-gated "jump and keep playing" path, whether or not the deck was already playing.
- **Effect ring-out, volume bug fixed:** the v1 `effect-ring-out.patch` silenced a channel's real dry volume (not just the effect's input) for the whole tail window, so switching FX focus away from a channel with a ringing Echo/Reverb - or turning the effect off - made that channel's volume disappear until the mix knob was cycled. The tail buffer now only starves the effect processor itself; the channel's own volume is never touched.
- **Rekordbox loop hot cues:** needs `rekordbox-loop-hotcues.patch` (stable 2, patch #16). A Rekordbox hot cue that is actually a saved loop now imports into Mixxx as a real Loop cue (correct start and end), instead of losing its length and becoming a plain point cue.
- **CUE also sets loop-in: REMOVED again.** Pressing CUE while a loop was active reset the loop's in point to the start of the song, so the main deck CUE buttons (`[ChannelN],cue_default`, status 0x90-0x93, midino 0x0C) are back to the plain `<normal/>` binding of the original mapping, and `PioneerDDJGRV6.cueSetLoopIn` is gone from the script. Copy `DDJ-GRV6-Custom.midi.xml` and `-scripts.js` to the Pi.
- **Key display, sharps only:** needs `key-display-sharps.patch` (stable 2, patch #17). The two enharmonic traditional-notation key names that used to show both spellings now show sharps only: `F♯/G♭` -> `F♯`, `D♯m/E♭m` -> `D♯m`. A sharp/flat choice in the future Settings tab is separate, later work; this patch only removes the double-spelling for these two keys.
- **Cue/Loop CALL, dual-mode (superseded in v0.8, see below):** mapping-only fix. `loop_halve`/`loop_double` (deck's CALL left/right, status 0x90-0x93, midino 0x51/0x53) now go through `PioneerDDJGRV6.loopHalveDoubleGated`. First cut of this: gated the buttons to a no-op unless a loop was already active, since Mixxx's own loop-halve/double code does not queue a seek without one and the reported track-start/end jump couldn't be explained from that code path. Superseded once the desired behaviour was confirmed: see v0.8.
- **Tempo fader center deadzone:** the 14-bit tempo slider (`tempoSliderMSB`/`LSB`) rarely lands on the exact digital center at its physical center point; the residual fraction of a percent was leaking into `[ChannelN],pitch` while keylock is off (pitch tracks rate live) and spuriously showing the KEY box's transposed-key block on tracks nobody pitched. `|faderRate| < 0.0005` (~4 MIDI ticks, ~0.05%) now snaps to a clean 0. Does not touch the fader's end-of-travel range - a separate calibration issue reported for deck 2 not quite reaching +-10%.

## Changes in version 0.7 (needs the "stable 2" patch build)

- **Browse loading banner:** needs `rekordbox-loading-spinner.patch` (stable 2, patch #18). `[Library],grv6_rekordbox_busy` is set while Mixxx scans a Rekordbox USB or parses a device's playlists (`RekordboxFeature`'s two `QtConcurrent` worker phases), cleared when each finishes. The skin shows it as a banner across the top of Browse ("LOADING REKORDBOX USB...") - legacy Mixxx skins have no floating/overlay layout, so this is a banner like the error banners, not a center-screen spinner icon.
- **Browse zoom, live:** needs `browse-zoom.patch` (stable 2, patch #19). `Library` gains a live `[Library],grv6_visible_rows` control (3-20, default 8): row height and font are derived from the viewport so exactly that many rows fit. SHIFT + the controller's BROWSE knob adjusts it (`PioneerDDJGRV6.browseKnobShiftZoom` in `controller/DDJ-GRV6-Custom-scripts.js`); clockwise = zoom in (fewer, taller rows), matching the Main tab's waveform-zoom direction. 0 (config-file only, not reachable from the knob) falls back to the manual RowHeight/Font Preferences settings. Corrected in v0.8: see below - SHIFT+rotate is its own CC, not the plain rotate CC with a shift flag.
- **Rekordbox playlists sorted by #:** needs `rekordbox-force-sort.patch` (stable 2, patch #20). Rekordbox track lists and playlists always open sorted by # (playlist position) ascending, instead of remembering whatever column was last sorted in a different source.
- **Rekordbox fixed column layout:** needs `rekordbox-fixed-columns.patch` (stable 2, patch #21). Rekordbox views show a fixed column set in the order #, Title, Artist, Key, Duration, with proportional widths that fill the viewport (# / Key / Duration sized to content, Artist/Title sharing the rest 40/60, Duration stretching to the right edge). Every other library source (Mixxx library, crates, playlists, other USB formats) is unaffected.
- **Key compatibility traffic light:** needs `key-traffic-light.patch` (stable 2, patch #22). In any Rekordbox or library table, the Key cell is highlighted green when it is Camelot-compatible (same key, relative major/minor, or +-1 step) with the "master" deck's key - master = the currently playing deck that started playing most recently; nothing is highlighted while no deck is playing. As a side effect, the Key column in every library table now always shows a fixed notation instead of following the Preferences key-notation setting (see the next patch for which one).

## Changes in version 0.8 (needs the "stable 2" patch build)

- **Key column shows Camelot notation:** needs `rekordbox-key-notation-and-bpm-sort.patch` (stable 2, patch #23). The Key column everywhere now shows Camelot-wheel notation (e.g. "8A") instead of the musical note names patch #22 first forced - the compatibility check itself is unaffected either way, since it works from the raw key value, not the display string.
- **Rekordbox playlists default-sort by BPM:** same patch (#23). Overrides patch #20's #-ascending default for Rekordbox specifically (the force-sort mechanism is unchanged, only which column it targets).
- **Rekordbox track color column:** needs `rekordbox-color-column.patch` (stable 2, patch #24). A narrow color swatch at the left edge of the Rekordbox table shows each track's Rekordbox color tag - the data was already being imported into the library's Color column, just never displayed; this reuses Mixxx's own color-cell rendering, no new drawing code.
- **Rekordbox BPM column:** needs `rekordbox-bpm-column.patch` (stable 2, patch #25). Fixed layout is now Color, #, Title, Artist, BPM, Key, Duration - BPM was already the default sort (#23) but had no visible column to click for a manual re-sort; now it does, same as every other column.
- **Duration column pushed off-screen, fixed:** needs `rekordbox-duration-column-fix.patch` (stable 2, patch #26). Reported after only the skin (not yet this build) was deployed, so it may have already been present with the pre-BPM-column 5-column layout too. `WTrackTableView::applyFixedColumnWidths()` relied entirely on `setStretchLastSection` (called in `loadTrackModel()`, *before* the column-reordering `moveSection()` calls) to size Duration - Qt could still have been tracking a different column as "last" for stretch purposes at that point. Duration's width is now also set explicitly (leftover viewport width, floored at its own content minimum), independent of whether the stretch mechanism kicks in correctly; `setStretchLastSection` stays too, so a live window resize still tracks.
- **Star rating column restored:** needs `rekordbox-rating-column.patch` (stable 2, patch #27). Was visible and working before patch #21's fixed column layout restricted the visible set; the underlying data was never the problem (Rekordbox star ratings have been imported into the library's Rating column since the very first Rekordbox patches). Fixed layout is now Color, #, Title, Artist, BPM, Key, Rating, Duration - reuses Mixxx's own `StarDelegate`, same as every other library table. The Browse info panel's separate `InfoStars` widget (top-right, bound to `[PreviewDeck1]`) is unrelated to this and still reported as not working - its wiring (`LegacySkinParser::parseStarRating`) looks structurally identical to the working `TrackProperty`/`Key`/`NumberBpm` widgets right next to it in the same info box, so the cause isn't obvious from the skin side; needs a direct comparison once this column is deployed (does a track that shows N stars in the new column also show 0 in the info panel when previewed?) to tell whether it's a data problem specific to `PreviewDeck1` or something else.
- **BPM column missing despite #25, fixed:** needs `rekordbox-force-show-columns.patch` (stable 2, patch #28). Reported after confirming the build with #25 was actually installed. Root cause: `WTrackTableView::loadTrackModel()` only ever calls `hideSection()` for columns that should be hidden, never `showSection()` for ones that should be visible - so BPM, hidden by an *earlier* session under patches #21-24 (before #25 exempted it from `isColumnInternal`), stayed hidden forever once Qt persisted that header state, regardless of what the model says now. Rekordbox's fixed columns are now force-shown on every load, overriding any stale persisted state; every other model (normal library, crates, playlists) is untouched and keeps respecting the user's own manual column choices. If BPM (or any fixed column) still doesn't show after this, the header state may need clearing from Mixxx's own Preferences (reset that table's layout) rather than anything skin/patch-side - ask before suggesting that, since it resets column choices for every other library view too.
- **Key notation in the deck panels, fixed for real (skin-attribute attempt reverted):** the skin's own `<Key>` widgets (`WKey` - Main tab, browse cards, deck strips, info box) were still showing Traditional ("Cm") after #23 forced Camelot in the *library table*, because that patch only touches `BaseTrackTableModel`'s Key column, a separate code path from `WKey`. First attempt was a skin manifest attribute (`<attribute config_key="[Library],key_notation">3</attribute>`, same technique as `ShowDurationRemaining`) - this did not work and was reverted, because `WKey` calls `KeyUtils::keyToString(key)` with no notation argument, which defaults to `KeyNotation::Custom` and reads a **static cache** (`KeyUtils::s_notation`) that is only ever populated by the Key Preferences page (`DlgPrefKey`) when it is constructed or changed there - it never reacts to `[Library],key_notation` being set live, from a skin attribute or anywhere else. Real fix needs `deck-key-camelot.patch` (stable 2, patch #29): `WKey::setValue()` now calls `keyToString(key, KeyUtils::KeyNotation::Lancelot)` directly, bypassing that cache entirely - the same technique the library table's Key column already uses.
- **BPM column's lock checkbox, actually removed:** the BPM cell has a built-in "lock this BPM" checkbox (`BPMDelegate`/`CheckboxDelegate`, `ObjectName LibraryBPMButton`) that protects a track's BPM from being changed by Mixxx's own re-analysis - not used on this kiosk, since BPM values come from Rekordbox's own analysis, not Mixxx's. It was never styled, so Qt drew its raw default indicator (a plain, unstyled box) - pre-existing, just easy to miss at stock row heights, reported once browse-zoom made rows big enough to notice it.
  - First pass styled it with Mixxx's own lock/unlock icons. Second pass, per follow-up ("if I don't use it, remove it"), tried collapsing it via `#LibraryBPMButton::indicator { width: 0px; height: 0px; }` - **this did not visibly work**, confirmed still showing after deploying it. Qt's item-view check indicator apparently does not respect `::indicator` width/height the way a real standalone `QCheckBox` would, and Mixxx's own documented styling comment for this exact widget only ever mentions swapping the icon image, never sizing it - QSS alone could not be trusted to actually fix this.
  - Third pass, `no-bpm-lock-checkbox.patch` (stable 2, patch #30): `BaseTrackTableModel::delegateForColumn()` no longer assigns `BPMDelegate` to the BPM column. **This also did not fix it** - confirmed on an installed `r9.1` (build #9, which contains #30), the box was still there. `delegateForColumn()` is `final` in the base class, so it could not be scoped to Rekordbox only; #30 applies to every library table. The `style.qss` rule from the failed CSS attempt was removed.
  - Real cause, `no-bpm-check-state.patch` (stable 2, patch #31): the model itself supplies the check state. `BaseTrackTableModel::roleValue()` answers `Qt::CheckStateRole` for the BPM column from the `bpm_lock` field, and *any* item delegate - including the default one #30 falls back to - draws a checkbox whenever the model supplies check-state data. Rekordbox's temp table has no `bpm_lock` column at all, so every cell answered "undecidable" (`Qt::PartiallyChecked`), drawn as a solid box - which is why it sat over the BPM number and clipped its leading digits ("3.8" for "93.8"). The BPM case is now dropped from the `CheckStateRole` switch, so BPM returns no check state at all. Same scope as #30 (every library table); the write side (`setData` toggling the lock) is untouched but unreachable once no indicator is drawn. Needs a build newer than #9.
- **Loop hot cues, always reseek (mapping-only, no new build needed):** reported that a hot cue whose loop was already the deck's "current saved loop" stopped jumping back to its start on repeat presses - it just toggled the loop on/off in place instead (Mixxx's own `CueControl::hotcueActivate`, Loop-type branch: once `m_pCurrentSavedLoopControl == pControl`, it calls `setLoop(..., !loopActive)` with no seek). Wanted instead: every press always jumps to the cue's start and (re)activates the loop from there, whatever state it was in. `PioneerDDJGRV6.hotcuePlay` now checks `hotcue_N_endposition` (only valid, i.e. `>= 0`, for a loop-type cue - `Cue::kNoPosition` = -1 otherwise) and routes loop-type hot cues to `hotcue_N_gotoandloop` instead of `hotcue_N_activate` - a stock Mixxx control (`CueControl::hotcueGotoAndLoop`) that already does exactly this unconditionally, every press, no toggle. Regular (non-loop) hot cues are untouched, still going through the existing non-gated `hotcue_N_activate` path below. No source patch needed - `gotoandloop` already exists in stock Mixxx.
- **Regular hot cue no longer stays bounded by a leftover loop:** follow-up to the above - pressing a *regular* (non-loop) hot cue while a loop hot cue's loop was still active kept the deck bounded by that old loop, since `hotcue_N_activate`'s HotCue branch (`CueControl::hotcueGoto`) only seeks, it never touches `loop_enabled`. `PioneerDDJGRV6.hotcuePlay` now explicitly sets `loop_enabled` to 0 before activating a regular hot cue. Loop-to-loop transitions (one loop hot cue overriding another) were already handled correctly by stock Mixxx (`setCurrentSavedLoopControlAndActivate` unconditionally reassigns the loop bounds), so nothing needed changing there.
- **Loop hot cue pad LEDs, fixed - real cause, not hardware:** reported the pad light turning off while its loop was active, back on when the loop wasn't. Not a hardware quirk: `HotcueControl::Status` has three values - `Empty=0`, `Set=1`, `Active=2` (loop currently enabled) - and every `hotcue_N_enabled` LED `<output>` in the mapping had `<minimum>0.5</minimum>` with no `<maximum>`, which Mixxx defaults to `1.0` (`DEFAULT_OUTPUT_MAX`, `legacymidicontrollermappingfilehandler.cpp`). The effective "lit" range was therefore `[0.5, 1.0]` - `Set` (1) fell inside it, but `Active` (2) fell *outside* it, so the LED went dark exactly while the loop was active. All 64 `hotcue_N_enabled` outputs (8 pads x 4 decks x normal/shift layer) now also have `<maximum>2</maximum>`, so both `Set` and `Active` count as lit; only `Empty` (no hot cue on that pad) stays dark, matching what was asked for. Mapping-only, no new build needed.
- **Track highlight:** the light top/bottom border added in v0.6 is gone (rendered as a stray line outside the orange fill in `QTableView::item` - a Qt stylesheet quirk). Bold text on the selected row stays.
- **ON AIR icon:** replaces the deck-column USB icon (`OnAirIcon`, was `UsbIcon`, in `deck_col.xml`). Lit red while `[ChannelN],volume` (the channel fader) is above 0, instead of while a track is loaded. New icon assets generated by `tools/make_images.py`'s `onair()` function; `usb_on/off.png` removed as unused.
- **Key Shift pad LEDs:** mapping-only, `PioneerDDJGRV6.keyShiftLed` in `controller/DDJ-GRV6-Custom-scripts.js`, connected to `pitch_adjust` like the existing `keySyncLed`. The pad matching the current shift amount blinks (250ms, same technique as the sampler-play blink); the "0" (normal pitch) pad is always lit solid so it is visually distinct from the blinking one. Confirmed on this hardware: almost every pad LED renders blue regardless of what this mapping sends, so the "0" pad shows up blue in practice - that is the controller's own fixed color for that pad slot, not something the script sets. Fixed a bug found after testing: the reset loop only cleared pads 1-7 (indices 0-6), so pad 8 (index 7) never got its LED touched and stayed lit from whatever state it started in. Also removed pad 8's `sync_key` action per feedback - no dedicated pad should silently sync to another deck - and made it a second reset-to-normal-pitch button instead (redundant with pad 4/index 3, which already does this; both are now lit solid at rest to mark them as reset buttons).
- **Cue/Loop CALL, dual-mode (corrected):** `PioneerDDJGRV6.loopHalveDoubleGated` now does what was actually wanted - while a loop is active, CALL left/right halve/double it (unchanged); while no loop is active, CALL left/right jump the playhead to the track start/end instead of doing nothing. - **Shift + BROWSE knob zoom, fixed:** confirmed via `aseqdump -p 20:0` that SHIFT+rotate is a genuinely separate MIDI message - Control Change, channel 6, CC 0x64/100 (not the plain rotate's CC 0x40/64 with a shift flag) - same relative-encoder convention (1 = +1, 127 = -1). Now: each `LoadButton` is a fixed square (was `SizePolicy me,me`) instead of stretching to whatever the grid cell happened to be; PREVIEW's own size is untouched. ## Changes in version 0.9 - Settings tab, first slice (skin + mapping only, no new Mixxx build needed)

The page follows the Settings design: four columns, eight numbered groups, segmented bars, on/off switches, steppers, EQ faders. All of it lives in one generator function (`settings_xml()` in `tools/build_skin.py`, output `settings.xml`) plus a `Settings tab` block at the end of `style.qss`; pictures (`eq_fader_*`, `sw_on/off`, `rec_on/off`) come from `tools/make_images.py`. The whole design is on the page. Parts without a backend are drawn INERT (labels instead of buttons) and carry a "NOT IMPLEMENTED YET" tag (`SetSoon`), and are wired up slice by slice: crossfader curve, load onto a playing deck, startup defaults (quantize, tempo range, time readout), VU sensitivity, USB sticks (static "USB 1" / "USB 2" examples), sleep + SLEEP NOW, POWER OFF. The About lines are static text. Every block and card has an explicit fixed height (Mixxx's layouts hand spare height to anything that might grow, which stretched the cards in the first version); only the cards the design lets grow take the rest of their column. Card margins are fixed-size spacer labels, because `qproperty-layoutContentsMargins` is ignored by widget groups.

How a control is built (learned the hard way, see below): a skin button can only write 1, and pressing an already-lit segment must not do anything. So a segment is a `WidgetStack` whose page index is the value of the setting; the lit page is a plain label, every other page is a button that writes 1 to an *action* push button (`[ChannelN],orientation_left` etc.) or, for skin toggles, flips the toggle.

Lessons from the first test (stable 3 build #1 + skin slice 1):
- Segments made of a label with a transparent button *stacked* on top did not respond to taps (only the presets did): in a `stacked` layout the FIRST child is on top (Qt's `QStackedLayout` lowers every widget added after the first; stock LateNight lists its invisible REC button first). A stacked toggle over a label therefore needs the button first. The design-based page avoids stacking: it swaps a label and a button with a `WidgetStack` instead. (`time_number.xml`'s transparent TIME/REMAIN toggle is built the old way, button second; if tapping the time cycles through three states instead of two, that is why.)
- Two-state skin buttons on a *plain* C++ control (`ControlObject`) can only ever write 1: the toggle behaviour lives in `ControlPushButton`, not in the widget. Skin-created controls are toggle push buttons, so those worked both ways; the first version of patch #32 used plain controls and TRADITIONAL / FLATS could not be switched back. Fixed with action push buttons.
- Browse table, last digit of Duration cut off (reported with the scroll bar showing): the Duration column is sized from the viewport width before the vertical scroll bar appears (patch #26), so it ends a few pixels under the bar. A stylesheet `::item { padding-right }` fixed it only for the SELECTED row (a padding-only `::item` rule is not applied to unselected items, and a background rule would override the traffic-light colours) and was removed. Real fix: stable 3 patch #35 `rekordbox-scrollbar-room` reserves the scroll bar's width in `applyFixedColumnWidths()`.
- Fixed-height groups that have a border (the Settings cards, the EQ band boxes): Mixxx counts the 1 px border INSIDE the height, so a card whose content adds up to exactly its height loses 2 px and its last row is clipped (the REC button lost its bottom edge). The generator adds the 2 px.
- Settings spacing system (constants `BAR`, `PAD`, `TIGHT` in `settings_xml()`, mirrored by `qproperty-layoutSpacing` in the QSS): controls 56 high, 8 between neighbours and inside a block, 16 between blocks and as card padding. Text beside a switch or button is centred against it.

- Hot cue mode GATE and loop hot cues: on a paused deck, a loop-type hot cue in GATE mode now uses Mixxx's own hot cue preview (`hotcue_N_activate`): plays the loop while the pad is held, back to the cue on release. Before, loop cues always used `gotoandloop` and ignored the mode. While playing, a loop cue still restarts its loop. The mode's normal setting is now called NORMAL (was JUMP AND PLAY).

Notes:
- Settings are stock `<attribute persist="true">` controls in `skin.xml`: the value there is only the first-run default. Mixxx writes them to `mixxx.cfg` when it exits cleanly (Ctrl+Q). **A power cut loses the changes made in that session** (including the crossfader assign), which is one more reason for a real POWER button later.
- Both "LOAD ..." switches default to OFF, so nothing behaves differently until they are turned on.
- The controller script should not `makeConnection` to `[Skin]` controls in `init()`: the controller can initialise before the skin exists (the same reason the `grv6_left_deck` notes above say to set those from a timer; start order not confirmed from the source). That is why the crossfader presets are done with skin-side multi-connection buttons instead of a script listener, and why `onLoadPress` only *reads* `[Skin]` controls when it fires.
- Stable 3 (`mixxx-build/patches/series-stable3`) = stable 2 + patches #32 (key style) and #33 (main EQ). The skin works on either build; only the MAIN EQ and KEY DISPLAY rows need stable 3. Stable 2 stays frozen as the known-good fallback (its debs are in `mixxx-build/stable2/`).
- Still to come: sleep mode, USB stick eject (needs a Pi-side helper).
